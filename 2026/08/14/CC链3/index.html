CC 链 3

今天我们继续接着前面的来讲，CC 链的各种链条实际上就是由简单的几个类和方法通过不同形式的拼接而成的。而每种链子呢也都会有各自的特征，像 CC 链 1 就会受到版本的限制，而 CC 链 6 呢则没有这种限制。但是他们依旧有一个共同点，就是都会通过 Runtime 来直接执行危险命令。

那么，如果这样的危险指令被 WAF 了，那我们又应该怎么办呢？接下来我们就需要用到一个特别的东西了，就是 Java 的类加载机制 ————如果我们能动态加载并实例化一个恶意类，那类里的静态代码块或构造方法中的恶意逻辑，就会在类加载时自动执行。这样，我们就不再需要显式调用 Runtime.exec() 了。

而CC3链，正是基于 TemplatesImpl 这个特殊类，利用它的 newTransformer() 方法触发自定义类的加载，从而把命令执行的逻辑转移到了恶意类的静态代码块中，完美绕过了基于Runtime的WAF检测。
