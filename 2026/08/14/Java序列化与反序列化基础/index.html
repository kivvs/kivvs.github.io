Java序列化与反序列化基础

Java序列化与反序列化基础

原生序列化和反序列化

	 Java 原生反序列化漏洞的根源，在于服务端将不可信字节流交给`ObjectInputStream.readObject()` 处理。反序列化过程不仅会恢复字段， 还可能触发目标 classpath 中已有类的回调逻辑和动态分派方法。

如果攻击者能够构造对象图，使这些调用最终到达危险操作，就可能造成信息泄露、SSRF、文件读写或远程代码执行。

为什么会产生安全问题？

当服务端使用 ObjectInputStream.readObject() 反序列化攻击者可控的数据时，JVM 会根据流中的类描述解析并实例化服务端 classpath 中已有的类。

若这些类或其依赖对象存在可利用的反序列化回调、动态方法调用和危险操作，攻击者就可能将它们组合成 Gadget Chain，最终触发 DNS 请求、文件操作、SSRF，甚至命令执行等效果。

注意：

  • 序列化流传递的是类名、字段值和对象关系，不是任意 Java 字节码。

  • 目标服务器必须已经存在对应类（通常来自 JDK 或第三方依赖）。

  • readObject() 自动执行，不等于一定能 RCE；还需要一条可达的 gadget chain 和危险 sink。

  • URLDNS 主要用于确认是否存在反序列化入口/出网 DNS 能力，不是 RCE 链。

可能的形式

  1. 入口类的readObject直接调用危险方法。
  2. 入口类参数中包含可控类，该类有危险方法，readObject时调用。
  3. 入口类参数中包含可控类，该类又调用其他有危险方法的类，readObject时调用。

比如类型定义为Object，调用equals/hashcode/toString

当容器字段或参数类型为 Object、接口类型或父类类型时，

反序列化过程可能发生动态分派。 例如：

方法 常见触发场景
hashCode() HashMap / HashSet 恢复元素、计算桶位置时常见
equals() 发生哈希碰撞、键比较时才可能触发，不一定必经
compareTo() TreeMap / TreeSet 恢复、排序或比较时常见
toString() 通常不是 HashMap.readObject() 的直接必经调用，需要其他调用点触发

▎ 核心：Java 的动态分派（多态调用）

▎ 当调用点的静态类型较宽泛（如 Object、接口或父类）时，运行时会执行实际对象重写后的同签名方法。

  1. 构造函数/静态代码块等类加载时隐式执行。
	需要注意：`Serializable` 对象的反序列化通常不会调用该类自身的普通构造器。

因此，反序列化漏洞分析的重点一般不是构造器，而是 readObject、 readResolve、

readExternal，以及对象恢复过程中触发的动态方法调用。

	 但对于 `Externalizable` 对象，反序列化会调用其 public 无参构造器，

随后执行 readExternal()，因此需要单独分析。

共同条件：

通常，能够直接参与 Java 原生对象流的对象需要实现Serializable 或 Externalizable。

但利用链并不要求“每个类都显式实现 Serializable”：

  • 被序列化对象图中的对象通常需要可序列化；

  • 父类可以不实现 Serializable；

  • 某些对象可通过代理、反射包装器或其他可序列化容器间接参与调用；

  • HashMap / HashSet 常见地触发 hashCode()；

    • 哈希冲突场景可能进一步触发 equals()；

    • TreeMap / PriorityQueue 等结构可能触发 compareTo() 或 Comparator；

    • 某些框架或异常处理逻辑可能触发 toString()。

    • Externalizable 还会引入 readExternal() / writeExternal() 这类更显式的回调。

HashMap中，由于Entry的存放位置是根据Key的Hash值来计算，然后存放到数组中的，

HashMap`不会直接序列化内部哈希桶数组，而是序列化逻辑上的键值对。反序列化时，它会重新创建桶数组，并逐个读取 key/value 后重新插入。这样做可以避免将内部实现细节（如桶数量、Node 链表/红黑树结构、阈值等）固化到序列化格式中，也使反序列化时能够依据当前实现重新计算元素位置。

重新插入元素时，HashMap 需要计算 key 的哈希值，因此会调用：key.hashCode()

反射

反射： Java 的反射机制是指在运行状态中，对于任意一个类都能够知道这个类所有的属性和方法； 并且对于任意一个对象，都能够调用它的任意一个方法；这种动态获取信息以及动态调用对象方法的功能成为Java语言的反射机制。

反射的作用：让java具有动态性

  • 修改已有对象的属性
  • 动态生成对象
  • 动态调用方法
  • 操作内部类和私有方法

在反序列化漏洞中的应用：

  • 定制需要的对象
  • 通过invoke调用除了同名函数以外的函数
  • 通过Class类创建对象，引入不能序列化的类
