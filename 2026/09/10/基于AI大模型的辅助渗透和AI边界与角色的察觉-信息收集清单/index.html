DVWA 信息收集清单（定制版 · 仅侦察 · 已补全）

  • 目标：http://localhost/dvwa/
  • 技术栈：Apache/2.4.39 (Win64) + PHP/7.3.4 (CGI/FastCGI, mod_fcgid) + MySQL/MariaDB（库名 dvwa）+ Windows WAMP 环境
  • 站点身份：Damn Vulnerable Web Application（DVWA，授权本地靶场，标题自证；版本含 api/authbypass/cryptography/open_redirect 模块，推断 ≥ 1.10）
  • 生成时间：2026-09-07 ｜ 补全轮次：已用 admin/password 登录完成鉴权后侦察
  • 图例：[已确认] = 已实测命中（只读 GET/HEAD/登录）；[待验证] = 需后续逐项确认；◆ = 高价值侦察点
  • 范围红线：本清单仅含信息收集（目录/参数/接口/技术指纹）。不含任何利用 payload、不含认证绕过/注入/命令执行探测——依用户要求，只做信息收集。

A. 技术指纹（Tech Fingerprint）

  • [已确认] Web 应用：DVWA（登录页 <title>Login :: Damn Vulnerable Web Application (DVWA)</title>）
  • [已确认] Web 服务器：Apache/2.4.39 (Win64)，含 OpenSSL/1.1.1b、mod_fcgid/2.3.9a、mod_log_rotate/1.02（Windows WAMP/XAMPP 类宿主）
  • [已确认] 后端语言 / 运行模式：PHP/7.3.4，Server API = CGI/FastCGI（与 mod_fcgid 一致）
  • [已确认] 数据库：MySQL / MariaDB，库名 dvwa（/setup.php 显示 “Installed database already exists”）
  • [已确认] PHP 扩展：MySQLi、mysqlnd、pdo_mysql、GD（来自 /phpinfo.php）
  • [已确认] 安全级别机制：四级 Low / Medium / High / Impossible（/security.php 选项确认）；实测默认下发 Cookie security=impossible
  • [已确认] 会话机制：PHPSESSID（HttpOnly + SameSite=Strict，Max-Age=86400）
  • [已确认] 认证：默认账密 admin / password 登录成功（响应 logged in as 'admin'，/index.php 200）
  • [已确认] 缓存策略：全站 Cache-Control: no-store, no-cache, must-revalidate + Pragma: no-cache
  • [已确认] 登录防护：登录表单含反 CSRF 隐藏字段 user_token（单引号属性），校验依赖会话，未带会话会被拒
  • [待验证] PHP display_errors 是否开启（DVWA 默认常开，便于信息收集；待 /phpinfo.php 确认 display_errors=On）

C. 接口/模块清单（Endpoint Inventory）

全部模块路径位于 /dvwa/vulnerabilities/<module>/，登录后 GET 均返回 200（已确认）。参数细节见 D 节。

C0 认证与配置

  • [已确认] GET/POST /dvwa/login.php — 登录（username,password,Login,user_token）
  • [已确认] GET /dvwa/logout.php — 注销
  • [已确认] GET /dvwa/security.php — 安全级别（Low/Medium/High/Impossible）
  • [已确认] GET /dvwa/setup.php — 数据库安装/重置（库名 dvwa 已装）

C1 标准漏洞模块（DVWA 经典集，全部 [已确认] 200）

模块 主题 入口参数（见 D）
brute 暴力破解 username,password,Login（POST）
exec 命令注入 ip,ping,Submit（POST）
upload 文件上传 uploaded(multipart),Upload,MAX_FILE_SIZE（POST）
fi 文件包含 page（GET）
sqli SQL 注入 id,Submit（GET）
sqli_blind SQL 盲注 id,Submit（GET）
xss_r 反射型 XSS name,XSS（GET）
xss_s 存储型 XSS txtName,mtxMessage,btnSign,btnClear,guestform（POST）
xss_d DOM 型 XSS default,XSS（GET，纯客户端）

C2 扩展模块（新版 DVWA ≥1.10，本次导航新发现 [已确认] 200）

模块 主题 入口参数（见 D）
api 不安全 API id（GET，疑似 REST 风格；具体端点待探）
authbypass 认证绕过 页面引用 User/admin 用户态（具体参数名 [待验证]）
cryptography 弱加密 v（GET）、check_token（表单）
open_redirect 开放重定向 redirect（GET，?redirect= 重定向目标）
  • [待验证] api 模块具体端点（如 /vulnerabilities/api/?a=...、/vulnerabilities/api/v1/...）。
  • [待验证] authbypass 模块参数名（疑似 ?user= / ?admin= / ?id= 类可篡改字段）。

  • [待验证] authbypass、api 模块精确参数名（页面源码未暴露明确表单，需进一步阅读）。

E. 信息收集下一步建议（仍为侦察，不涉及利用）

  1. 版本精确认定：从 /about.php、/index.php 页脚或 /docs/ 取得 DVWA 精确版本号（当前推测 ≥1.10，依据为 4 个扩展模块存在）。
  2. 目录枚举：对 /dvwa/ 跑字典枚举，补全 B 节遗漏路径与备份文件。
  3. api 模块端点枚举：阅读 /vulnerabilities/api/ 页面，确认 REST 端点路径与参数。
  4. authbypass 参数确认：阅读页面源码，确认可篡改的认证相关参数名。
  5. 安全级别差异观察：遍历 security Cookie 四值，记录各模块在 low/medium/high/impossible 下的参数与行为差异（仅观察，不改写利用）。
  6. /phpinfo.php 取证：确认 display_errors、allow_url_include、magic_quotes_gpc 等与安全相关的 PHP 指令。

F. 已确认边界（避免误报）

  • 未部署 phpMyAdmin、无独立 /admin/、无 .git 泄露。
  • /dvwa/docs/ 仅 403，子文件（README.html 等）均 404，不公开。
  • /dvwa/config/config.inc.php 返回 200 但为 PHP 执行结果，源码未直出。
  • 会话 Cookie 带 HttpOnly + SameSite=Strict。
  • robots.txt 内容 Disallow: /（全站屏蔽，已读取）。
  • 数据库 dvwa 已安装，默认账密 admin/password 可登录（授权本地靶场）。

注：依据”只做信息收集”要求，本清单不含任何利用 payload 与攻击验证步骤。E 节仅列后续侦察动作，所有动作均限定为只读/被动指纹收集。
