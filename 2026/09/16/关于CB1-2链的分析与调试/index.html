Apache Commons BeanUtils 是一个 Java 库，作为更大的 Apache Commons 项目的一部分。它提供了一组实用方法和类，用于操作 Java Bean。Java Bean 是一种遵循特定命名约定的 Java 类，具有一组属性和访问它们的 getter 和 setter 方法。

Commons BeanUtils 库在许多 Java 应用程序和框架中广泛使用，例如 Apache Struts 和 Spring Framework。它可以简化代码，提高开发效率，并有助于降低维护成本。

CB2 与 CB1 的差异

细心复现过 CB 链的师傅应该能够发现，CB1 和 CB2 的利用环境存在一个小小的差异，那就是 CB2 并不依赖 CC 环境。那么这又是为什么呢？

CB1 使用 BeanComparator 的无参构造，默认比较器是 ComparableComparator，来自 commons-collections。如果目标环境没有这个库，或者版本不匹配（如 Shiro 自带 CC 4.0 而本地用 CC 3.2.1），反序列化会因 serialVersionUID 不一致而失败。

而在CB1中，调用的BeanComparator类，是直接进行声明对象调用的

该调用方式直接调用BeanComparator的无参构造方式，无参构造方式又会传递个null值去调用带一个参数的构造方法，该方法又会调用ComparableComparator.getInstance()方法去调用public BeanComparator( String property, Comparator<?> comparator )的构造方法

其中调用ComparableComparator.getInstance()，调用的ComparableComparator类为commons-collections组件的类，意味着CB1链是依赖于CC组件的，如果目标环境不存在CC组件那么就无法使用CB1链。

因此CB2链的核心变动就是BeanComparator类的声明方式，规避使用到ComparableComparator类作为comparator比较器，因此只需要替换一下comparator比较器，找一个java自带或者cb组件自带的实现了comparator和序列化的比较器类即可。

具体分析

我们直接来看到在 CB2 中我们需要用到的AttrCompare类，它同样也实现了comparator和序列化。

AttrCompare 位于 com.sun.org.apache.xml.internal.security.c14n.helper，是 JDK 自带的类，不依赖任何第三方包。这样 Payload 中完全不含 commons-collections 的类，在 Shiro 等受限环境下也能正常反序列化

并且因为BeanComparator类的触发为BeanComparator.compare方法中getter/setter获取对象方法进行反射调用，我们并不需要理会这个类里面具体的调用方法。只需要利用 BeanComparator的带参构造即可。

其他条件不需要任何变化

Gaget chain

CB2 的 Gadget 链本质上与 CB1 完全一致，触发路径没有区别。唯一的改动在于 **BeanComparator** 使用的比较器，目的是摆脱对 commons-collections 的依赖。

poc

总结

总的来说，CB2 链就是在 CB1 链的基础上，将触发入口点的方式从无参进入替换为 AttrCompare方法。从本质上来看，两条链子都是从PriorityQueue.readObject → BeanComparator.compare → TemplatesImpl.getOutputProperties → 命令执行。在BeanComparator类进行compare比较时，会调用getter/setter javabean去获取比较对象的方法，若存在get/set对应的方法，则通过反射执行该类的该方法。
