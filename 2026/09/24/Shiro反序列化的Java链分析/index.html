今天，我们来见一下之前并不熟悉的东西，那就是 shiro

Shiro 是一款轻量级的 Java 安全框架，提供了身份认证、授权、加密和会话管理等功能。它可以集成到任何 Java Web 应用程序中，并且易于使用和扩展。Shiro 的设计理念是简洁而灵活，不仅可以应用于 Web 应用程序，还可以应用于命令行、移动设备和分布式系统等各种应用场景。

shiro 提供了包括权限控制、会话管理以及加密解密的功能，它可以与各种 Web 框架和数据源集成，以满足不同应用场景的需求。

那么，我们今天要讲的链子主要涉及到 shiro 的加密与解密算法(AES），这个功能原本目的是用来保护用户的个人信息和隐私，防止其被黑客攻击和非法访问，但是在这里，我们相反地，就可以利用这一个功能来构造恶意 shiro 反序列化链子，通过加密后的 payload 执行一些恶意的命令。

shiro550

初见

接下来，我们开始对于这个 shiro550 靶场进行分析，首先，我们利用已知账号，同时勾选 remember me 进行登录

登录之后抓包发现 cookie 中有一个rememberMe参数，这里的值一看就是 base64 加密之后的数据，这就是 shiro550 的典型特征。那么，针对这样的 shiro550 反序列化题目，我们应该怎么做呢？

分析

不急着做题，我们首先来分析一下这条链子。

首先在 IDEA 中用 shift + shift 对 cookie 相关文件进行查找

存在CookieRememberMeManager.java这个文件，其中，getRememberedSerializedIdentity方法尤为重要，我们就从这里开始分析。

这个函数的主要功能就是确认请求和相应对象合法的情况下，读取 rememberMe 的 cookie值，并将其进行 base64 解码为字节数组并返回。

我们看一下是谁调用了这个函数，然后找到了是在AbstractRememberMeManager.java的getRememberedPrincipals方法之下

这个函数会自动获取从 RememberMe Cookie 中获取字节数组并调用convertBytesToPrincipals函数，这个函数会对数据进行反序列化并解密为PrincipalCollection（即用户身份集合）

看完反序列化，我们继续看到这个解密函数。默认情况下认为数据未加密，通过getCipherService()获取配置的加密服务，如果加密服务不为空，则调用cipherService.decrypt(encrypted, getDecryptionCipherKey())，使用解密密钥对数据进行解密。

接下来我们就来看到解密函数，这里实际上是一个接口，根据函数构造，推测这是一个对称加密。
